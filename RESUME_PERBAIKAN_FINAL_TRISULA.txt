[FIX-001] Password Default NRP Diganti Sandi Acak + Wajib Ganti Sandi
------------------------------------------------------------------------

  File Terdampak  : includes/functions.php
                    sql/update_schema.php
                    sql/schema.sql
  Kategori        : Keamanan - Manajemen Kata Sandi
  Severity        : KRITIS

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Fungsi ensure_personel_user() menggunakan NRP prajurit sebagai kata
  sandi default (password_hash($nrp)). Fungsi reset_user_password_to_nrp()
  juga me-reset sandi ke nilai NRP dalam teks terang. Karena NRP bersifat
  publik/diketahui rekan, seluruh akun yang menggunakan sandi default
  memiliki kerentanan kritis terhadap akses tidak sah.

  Contoh kerentanan:
    - NRP personel: "11020012345678" -> Kata sandi: "11020012345678"
    - Siapapun yang tahu NRP dapat login sebagai personel tersebut

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  ensure_personel_user() sekarang menggunakan random_bytes(4) menghasilkan
  8 karakter acak alfanumerik huruf kapital (contoh: E48A1B9F) sebagai
  kata sandi sementara. Flag must_change_password=1 ditetapkan otomatis.
  reset_user_password_to_nrp() juga diperbarui dengan mekanisme sama.
  Kolom must_change_password TINYINT(1) DEFAULT 0 ditambahkan ke tabel
  users via sql/update_schema.php (migrasi aman, tidak merusak data lama).

  Contoh sandi acak yang dihasilkan:
    - Sandi #1: 0D70C2CC   Sandi #2: A4508327   Sandi #3: AEEBAD5F

  DAMPAK: Menghilangkan vektor serangan credential stuffing berbasis NRP.
          Sandi tidak lagi bisa ditebak oleh siapapun.

[FIX-002] Upgrade Validasi Kompleksitas Password (Min 6 -> Min 8+Kombinasi)
------------------------------------------------------------------------

  File Terdampak  : register.php
                    personel/profile.php
                    admin/settings.php
  Kategori        : Keamanan - Kebijakan Kata Sandi
  Severity        : TINGGI

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Validasi kata sandi di register.php hanya memeriksa panjang minimum
  6 karakter tanpa syarat kompleksitas. Personel dapat membuat kata
  sandi sederhana seperti "123456" atau "abcdef" yang sangat mudah
  ditebak atau di-brute-force.

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Validasi diperbarui serentak di tiga halaman:
    - register.php (halaman pendaftaran mandiri)
    - personel/profile.php (halaman ganti sandi personel)
    - admin/settings.php (halaman ganti sandi administrator)

  Aturan baru:
    - Minimum 8 karakter
    - Harus mengandung minimal 1 huruf (A-Za-z)
    - Harus mengandung minimal 1 angka (0-9)

  Pesan error yang ditampilkan:
    "Kata sandi minimal 8 karakter dan harus mengandung kombinasi
     huruf dan angka."

  Hasil Test Validasi:
    'abc123'    (< 8 karakter)    -> DITOLAK  [PASS]
    'abcdefgh'  (tanpa angka)     -> DITOLAK  [PASS]
    '12345678'  (tanpa huruf)     -> DITOLAK  [PASS]
    'Abc12345'  (valid)           -> DITERIMA [PASS]

  DAMPAK: Meningkatkan entropi kata sandi secara signifikan dan
          mengurangi risiko brute-force attack.

[FIX-003] Harmonisasi Teks Modal Alur Verifikasi Berjenjang
------------------------------------------------------------------------

  File Terdampak  : register.php (bagian modal sukses)
  Kategori        : Konsistensi UI - Pengalaman Pengguna
  Severity        : SEDANG

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Teks pada modal konfirmasi setelah pendaftaran berhasil menggunakan
  istilah yang tidak konsisten dan berbeda dengan alur verifikasi
  berjenjang yang sebenarnya (Personel -> Operator -> Admin). Hal ini
  membingungkan prajurit yang baru mendaftar.

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Teks modal diperbarui agar konsisten dengan alur 3 tahap:

    "Akun Anda sedang menunggu verifikasi bertahap:
     (1) Operator Satuan akan memverifikasi data kedinasan Anda,
     (2) Admin akan melakukan persetujuan akhir.
     Anda dapat login setelah kedua tahap verifikasi selesai."

  DAMPAK: Menyamakan ekspektasi pengguna dengan alur sistem yang
          sesungguhnya, mengurangi pertanyaan berulang ke operator.

------------------------------------------------------------------------
[FIX-004] Implementasi Paginasi Server-Side pada Halaman Laporan
------------------------------------------------------------------------

  File Terdampak  : admin/report.php
  Kategori        : Performa - Skalabilitas Query
  Severity        : TINGGI

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  admin/report.php memuat SELURUH data personel ke memori PHP sekaligus
  tanpa batasan, kemudian me-render semua baris ke HTML dalam satu
  permintaan. Dengan ratusan atau ribuan personel, halaman dapat:
    - Timeout (PHP max_execution_time terlampaui)
    - Out of Memory (PHP memory_limit terlampaui)
    - Browser hang karena terlalu banyak DOM element

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Ditambahkan sistem paginasi server-side:
    - Parameter ?per_page (pilihan: 10, 25, 50, 100) -- default: 25
    - Parameter ?page untuk navigasi antar halaman
    - Fungsi render_pagination() merender kontrol navigasi
    - Mode cetak (?print_all=1 atau ?all=1) tetap memuat semua data
      untuk keperluan cetak formal tanpa paginasi

  DAMPAK: Respons halaman lebih cepat, tidak timeout, dapat digunakan
          dengan data ribuan personel tanpa masalah memori.

------------------------------------------------------------------------
[FIX-005] Batas Keamanan Batch Bulk Download Berkas ZIP
------------------------------------------------------------------------

  File Terdampak  : admin/bulk_download.php
  Kategori        : Performa - Keamanan Server
  Severity        : TINGGI

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Fitur unduhan massal ZIP tidak memiliki batasan jumlah berkas.
  Admin dapat memicu unduhan dengan ratusan berkas PDF sekaligus,
  menyebabkan:
    - Konsumsi RAM server berlebihan (setiap PDF dibaca ke memori)
    - Timeout saat generate ZIP besar
    - Risiko DoS (Denial of Service) tidak sengaja

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Ditambahkan batas maksimum: tidak lebih dari 100 personel per
  operasi unduhan ZIP. Query personel dibatasi dengan LIMIT 100.
  Pesan informatif ditampilkan jika limit terlampaui.

  DAMPAK: Mencegah DoS tidak sengaja dan menjaga stabilitas
          server produksi saat digunakan banyak admin bersamaan.

------------------------------------------------------------------------
[FIX-006] Penghapusan Pemanggilan DDL Redundan dari config.php
------------------------------------------------------------------------

  File Terdampak  : config/config.php
                    sql/update_schema.php
  Kategori        : Arsitektur - Efisiensi Startup
  Severity        : SEDANG

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Fungsi ensure_v_personel_lengkap() dipanggil di config/config.php,
  sehingga dieksekusi pada SETIAP permintaan HTTP. Fungsi ini memeriksa
  dan membuat ulang VIEW database (CREATE OR REPLACE VIEW) pada setiap
  page load. Ini adalah pola "DDL on every request" yang:
    - Menambah latensi setiap halaman
    - Dapat menyebabkan table locking pada database sibuk
    - Mencampurkan concern "infrastruktur DB" dengan "runtime logic"

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Pemanggilan ensure_v_personel_lengkap() dihapus dari config.php.
  Pemeliharaan VIEW dipindahkan sepenuhnya ke sql/update_schema.php
  yang hanya dijalankan secara manual saat migrasi/pembaruan skema.
  Komentar penjelas ditambahkan di config.php:
    "// View relasional v_personel_lengkap kini dipelihara via
     //  skrip migrasi/utilitas pangkalan data"

  Migrasi kolom must_change_password juga diintegrasikan di file yang
  sama untuk sentralisasi semua operasi DDL.

  DAMPAK: Mengurangi overhead per-request dan memisahkan concern
          infrastruktur dari logika runtime aplikasi.

[FIX-007] Perbaikan Redirect Admin saat must_change_password=1 (Bug 403)
------------------------------------------------------------------------

  File Terdampak  : login.php
  Kategori        : Bug Kritis - Keamanan dan Role Management
  Severity        : KRITIS

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Ketika administrator login dengan flag must_change_password=1, sistem
  me-redirect ke /personel/profile.php yang membutuhkan:
    require_role('personel');
  Akibatnya admin langsung mendapatkan:
    "403 - Akses Ditolak: Halaman ini khusus untuk peran personel."
  Admin terjebak: tidak bisa mengakses apapun, tidak bisa ganti sandi.

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Logika redirect di login.php diperbarui dengan pemeriksaan role:

    if ($SESSION['user']['role'] === 'admin') {
        redirect('/admin/settings.php?action=change_password_required
                  #ganti-sandi');
    } else {
        redirect('/personel/profile.php?action=change_password_required');
    }

  Hasil Test Redirect:
    admin    + must_change=1 -> /admin/settings.php#ganti-sandi [PASS]
    personel + must_change=1 -> /personel/profile.php            [PASS]
    admin    + must_change=0 -> /admin/dashboard.php             [PASS]
    personel + must_change=0 -> /personel/dashboard.php          [PASS]

  DAMPAK: Menghilangkan bug 403 untuk admin. Alur force-change-password
          kini berfungsi benar untuk semua role.

[FIX-008] Guard Bypass URL untuk Pengguna Wajib Ganti Sandi
------------------------------------------------------------------------

  File Terdampak  : includes/auth.php
                    personel/profile.php
  Kategori        : Keamanan - Kontrol Akses
  Severity        : KRITIS

  KONDISI SEBELUM:
  ~~~~~~~~~~~~~~~~
  Meskipun login.php me-redirect pengguna dengan must_change_password=1
  ke halaman ganti sandi, pengguna dapat mem-BYPASS perlindungan ini
  dengan mengakses langsung URL lain:
    http://localhost/edosir-tni/personel/dashboard.php  <- bisa diakses!
    http://localhost/edosir-tni/personel/upload.php     <- bisa diakses!
    http://localhost/edosir-tni/personel/scan.php       <- bisa diakses!

  Selain itu, saat tiba di profile.php, tidak ada panduan visual yang
  jelas kepada pengguna tentang apa yang harus dilakukan.

  KONDISI SESUDAH:
  ~~~~~~~~~~~~~~~~
  Guard ditambahkan di dalam fungsi require_login() (includes/auth.php):

    Jika must_change_password=1 DAN
    URL bukan halaman ganti sandi DAN
    URL bukan /logout.php
    -> Redirect ke halaman ganti sandi yang sesuai

  Loop redirect dicegah dengan:
    strpos($currentUri, $allowedPath) !== false

  Hasil Test Guard:
    /personel/dashboard.php  -> REDIRECT (PASS)
    /personel/upload.php     -> REDIRECT (PASS)
    /personel/profile.php    -> IZIN     (PASS)  <- halaman tujuan
    /logout.php              -> IZIN     (PASS)  <- diizinkan logout
    /admin/dashboard.php     -> REDIRECT (PASS)
    /admin/settings.php      -> IZIN     (PASS)  <- halaman tujuan admin

  UX Tambahan di personel/profile.php:
    1. Banner peringatan merah di atas halaman:
       "Akun Anda menggunakan kata sandi sementara. Anda WAJIB
        mengganti kata sandi sebelum dapat menggunakan fitur lainnya."
    2. ID anchor #ganti-sandi pada kartu form password
    3. Auto-scroll JavaScript ke form ganti sandi (300ms setelah load)
       + highlight outline merah pada kartu tersebut

  DAMPAK: Menutup celah bypass sepenuhnya. UX lebih jelas dan
          informatif untuk pengguna baru yang menerima sandi sementara.

BAB V. KESIMPULAN DAN REKOMENDASI
================================================================================

1. KESIMPULAN
   -----------
   Analisis komprehensif terhadap aplikasi E-Dosir TRISULA TNI AD berhasil
   mengidentifikasi 8 (delapan) temuan yang mencakup aspek keamanan sistem,
   kualitas validasi data masukan, konsistensi antarmuka pengguna, performa
   sistem, dan arsitektur kode. Seluruh 8 perbaikan telah berhasil
   diimplementasikan dalam satu sesi kerja tanpa mengganggu fungsionalitas
   sistem yang sudah berjalan.

   Ringkasan per kategori:
     - KRITIS (3 temuan): FIX-001, FIX-007, FIX-008 -> Semua selesai
     - TINGGI  (3 temuan): FIX-002, FIX-004, FIX-005 -> Semua selesai
     - SEDANG  (2 temuan): FIX-003, FIX-006          -> Semua selesai

2. TEMUAN UTAMA
   ------------
   a) Kerentanan KRITIS: Penggunaan NRP sebagai sandi default membuka peluang
      takeover akun secara massal karena NRP bersifat publik.

   b) Kerentanan KRITIS: Bug redirect 403 pada admin dengan must_change_password
      menyebabkan admin terjebak tidak bisa melakukan apa-apa.

   c) Kerentanan KRITIS: Perlindungan must_change_password dapat di-bypass
      melalui akses URL langsung tanpa melalui login.php.

   d) Kerentanan TINGGI: Kebijakan sandi lemah (min 6 tanpa kompleksitas)
      sangat mudah di-brute-force oleh pihak tidak berwenang.

   e) Kerentanan TINGGI: Tidak ada batasan pada operasi bulk download dapat
      menyebabkan server tidak responsif (DoS tidak sengaja).

   f) Temuan SEDANG: DDL query (CREATE VIEW) dieksekusi setiap request
      menimbulkan overhead performa yang tidak perlu pada setiap page load.

   g) Temuan SEDANG: Inkonsistensi teks UI dapat membingungkan pengguna
      tentang alur verifikasi yang sebenarnya berlaku.

3. REKOMENDASI LANJUTAN
   ---------------------
   a) MODULARISASI: Pertimbangkan memecah includes/functions.php (1400+ baris)
      menjadi modul terpisah: auth_helpers.php, dosir_helpers.php,
      report_helpers.php untuk maintainability jangka panjang.

   b) RATE LIMITING: Implementasikan pembatasan percobaan login (login attempt
      throttling) untuk mencegah brute-force yang lebih canggih.

   c) TWO-FACTOR AUTH: Untuk sistem militer, pertimbangkan lapisan verifikasi
      tambahan OTP melalui aplikasi authenticator.

   d) AUDIT LOG: Perkuat pencatatan activity_log dengan memasukkan data sesi
      dan tindakan sensitif secara lebih detail dan terstruktur.

   e) BACKUP OTOMATIS: Implementasikan rutinitas backup basis data terjadwal
      mengingat data dosir personel bersifat sangat kritis dan rahasia.
